## 依頼：レンジャーズストライク「デッキ作成画面」のUX/UI再設計

### 1. 背景・目的

ブラウザ版TCG「レンジャーズストライク」のデッキ作成画面を、スマートフォン・タブレット・PCのすべてで**視認性と操作効率が高い**画面に作り替えたい。  
現行実装は動作しているが、初見の発見性・モバイルでの往復スクロール・フィルタの分かりにくさなどUX課題がある。  
**デザイン候補を2〜3案**と、採用案を実装できる**画面仕様書**を提案してほしい。

### 2. プロダクト文脈

- ユーザーは1,849枚のカードプールから40枚の自作デッキを組む
- 保存先はブラウザ localStorage（端末ローカルのみ）
- 保存後はスタート画面からCPU対戦に使う
- 対象ユーザー：カジュアル〜中級のプレイヤー（スマホ操作を最優先、PCでも快適に）

### 3. 現行画面の構成（改善のたたき台）

上から下へ縦積み（PCのみ2カラム）：

1. ヘッダー（戻る / 「デッキ作成」 / 枚数表示）
2. デッキ名入力（最大40文字）
3. ツールバー（スターター5種から一括読込 / クリア）
4. 検証エラー（40枚未満・同名上限など）
5. **デッキ内容パネル**（入っているカード一覧、±で枚数調整）
6. **カード追加パネル**（検索・収録セット・タイプ・カテゴリフィルタ・一覧）
7. 部分実装カードの警告バナー
8. 固定フッター（編集時：削除 / 保存）

### 4. 現行のUX課題（優先して解決したい）

| 課題 | 現状 | 望ましい方向性 |
|------|------|----------------|
| 発見性 | 検索しないとカード一覧が出ない（1,849件の性能制約） | 空状態でも「次に何をすればよいか」が一目で分かる |
| モバイル操作 | デッキ内容が上・カタログが下で、追加のたびにスクロール往復 | 片手操作・往復スクロール最小化 |
| 収録セット | 約80件の`<select>`、グルーピングなし | 絞り込みしやすいUI |
| カテゴリ | 略称（ET/WB等）のみ表示 | 初見でも意味が伝わる |
| 安全 | 戻る・クリアで未保存内容が消える（確認なし） | 誤操作防止 |
| 視認性 | デッキ行に実装ステータスバッジなし、画像未用意カードが多い | テキスト・バッジ・レイアウトで識別しやすく |
| 進捗感 | 40枚中何枚かが弱い | 常に進捗が視界に入る |

### 5. 変更してはいけない制約（ビジネス・技術）

#### 必須機能（削除・弱体化不可）

- 40枚デッキ、同名上限・禁止カード等のルール検証と日本語エラー表示
- 検索（名前 or ID）＋ 収録セット / ユニット・オペ / カテゴリフィルタ
- スターター5種の一括読込
- カード詳細モーダル（サムネタップ）
- 実装ステータスバッジ（Core / DSL対応 / UI未確認 等）
- 部分実装警告（保存はブロックしない）
- localStorage 保存、編集・削除

#### 技術制約

- Webアプリ（React / CSS、ダークテーマ基調）
- カタログ1,849件は**一括DOM描画不可** → 検索入力後に仮想スクロールリスト（行高72px固定）
- タッチターゲット最小 44px 推奨（現行36px）
- `aria-label` / `role="alert"` 等のアクセシビリティ維持

#### スコープ外（今回の提案に含めない）

- サーバー同期、URL共有、マルチプレイ
- ドラッグ&ドロップでのカード追加（将来案として言及は可）
- 公式大会ルールの完全再現

### 6. レスポンシブ要件

| ビューポート | 想定 | 設計上の期待 |
|-------------|------|-------------|
| 〜639px（スマホ） | 390×844 基準 | 片手操作、主要アクションは親指圏、縦スクロール最小 |
| 640〜1023px（タブレット） | 縦・横両方 | 余白活用、リスト高さ拡大、2ペイン検討可 |
| 1024px+（PC） | デスクトップ | デッキ内容とカタログの同時視認、効率的な追加フロー |

### 7. 出力してほしい成果物

#### A. デザイン候補 2〜3案（各案に以下を含む）

- コンセプト名と一言（例：「タブ切替型」「スプリットビュー型」「ボトムシート型」）
- 情報アーキテクチャ（ワイヤーフレーム：スマホ縦 / タブレット横 / PC）
- 主要ユーザーフロー：新規作成 → スターター読込 → 検索追加 → 40枚確認 → 保存
- 空状態・エラー状態・警告表示の見せ方
- 強み・弱み・向いているユーザー

#### B. 推奨案の詳細仕様（実装者がそのまま使える粒度）

- 画面要素一覧（コンポーネント単位）
- 各ブレークポイントのレイアウト（寸法・sticky/fixed の有無）
- インタラクション仕様（タップ、フィルタ変更、保存 disabled 条件）
- タイポグラフィ・色・コントラスト（WCAG AA 目標）
- 状態設計：default / hover / focus / disabled / error / empty
- アクセシビリティ（キーボード、スクリーンリーダー）

#### C. 現行からの差分マトリクス

| 要素 | 現行 | 提案 | 変更理由 |
|------|------|------|----------|
| （提案時に記入） | | | |

#### D. 実装フェーズ案

- **Phase 1（MVP改善）：** レイアウト・ナビのみ
- **Phase 2：** フィルタUX・空状態ショートカット
- **Phase 3：** 将来拡張（任意）

### 8. 評価基準（案の比較に使う）

各案を5段階で採点し、総合推奨を1案示すこと：

1. 初見の分かりやすさ（空状態・次アクション）
2. モバイル操作効率（追加1枚あたりの操作数・スクロール量）
3. 視認性（枚数進捗・カード識別・エラー視認）
4. 誤操作防止（未保存・クリア）
5. 実装コスト（既存Reactコンポーネントとの親和性）
6. アクセシビリティ
