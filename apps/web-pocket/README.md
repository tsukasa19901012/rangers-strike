# apps/web-pocket — ブラウザ版（PocketJS）

Rangers Strike の Web 版です。旧 Next.js 版（`apps/web`）を置き換えます。
UI は Vita 版と同じ [PocketJS](https://github.com/pocket-stack/pocketjs)（Solid）で書き、ゲームの進行・CPU・デッキルールは
`packages/client-core` と `packages/engine` をそのまま使います。ビルド結果は静的ファイルだけで、どの静的ホスティングにも置けます。

- タイトル: 自分と CPU のデッキ（スターター 46 種・自作）と CPU レベル（Lv1〜5）を選んで対戦開始。デッキ構築へ
- 対戦: 左にカード詳細（マウスを乗せたカード。カテゴリ・特徴・作品名など）、中央に盤面（CPU / 自分のラッシュ・バトル・コマンド・手札、
  山札・捨札・パワー）、右にフェイズと「フェイズ終了」ボタン。カードをクリックするとそのカードでできる操作が
  横に出て、対象が要る操作は対象が光ります。効果の選択や支払いは選択ウィンドウに出ます。
  選択ウィンドウには、いま聞いている効果の文（カードに効果が複数あればその1つ）も出ます（スマホでは詳細欄がないため。XG3-046 の撃破時の確認で何を聞かれているか分からなかった件）。カードの下には、山札から選べるカードは「選択可能」、一緒に並ぶ選べない山札のカードは「対象外」、山札に戻す順番を選ぶ窓や上か下かを選ぶ窓のカードは「選択対象」、ほかは場所（自バトル など）が出ます（client-core の `label` を切らずに表示）。
  好きな枚数のカードを選ぶ効果（超変身など）は、カードを選ぶとチェック（緑の枠と ✓、「✓選択中」）が付き、もう一度選ぶと外れます。「選択を確定（N枚）」で確定します（client-core の check window）。
  常駐に重ねたカードを選べる効果（XG6-048【鏡像の戦士】など）では、重ねたカードも「自重ね」として並びます（ウラ向きのものは裏のまま）。
  ラッシュフェイズでは、ラッシュの支払いに使えるコール（※コールMA など）を持つ場のユニットも光ります。クリックすると「コール（ホールドしてラッシュするカードを選ぶ）」が出て、選ぶと選択ウィンドウにそのユニットで払える手札のカードが並びます。カードを選ぶと、コマンドではなくそのユニットをホールドしてラッシュします（「コールをやめる」で閉じる。手札のカードをそのユニットへドラッグしても同じ。手札のカードから始めたときは、選択ウィンドウでコマンドとコールのユニットのどちらでも選べます）。
  自分のユニットがバトルエリアに出ると、そのユニットの横に「アタック / ストライク / 何もしない」がタップなしで出ます。
  光っている敵ユニットをそのままクリックしてもアタックできます（閉じると盤面から今までどおり操作できます）
  自動進行（設定）で、できる行動が「フェイズ終了」しか残っていないためにラッシュ／バトルフェイズを自動で終えたときは、上部に「できる行動がないのでラッシュ終了」を通常の倍の時間出し、ログにも「（できる行動がないのでラッシュフェイズを自動で終了）」を残します（効果を使った直後に終わると、効果のせいで終わったように見えた件。ログの行は画面側だけのもので、盤面の共有には入りません）
  スタートフェイズで選ぶことが残っているとき（自動進行のスタートフェイズ自動を切っている、戻す順を選べる、
  スタートフェイズに使える効果がある）は、「スタートフェイズ」のポップアップがフェイズ終了ボタンの横に出ます。1つ選ぶたびに残りが出ます。前のターンを「ターン終了」で終えたあとも出ます（以前はそのボタンの印が次のターンまで残り、ポップアップもバトルエリアへ出たときのポップアップも開かないことがありました）
  パワーはパワーゾーンの枚数ではなく、相手コマンドゾーンのマルチカテゴリ 1 枚につき +1 した数を出します
  （例: `パワー 4(裏1・マルチ+1)`。各プレイヤーの行の上の帯も `パワー4(…)`）
  帯は略語を使わず `CPU ダメージ0/7 手札7 パワー0 コマンド0` のように書きます。山札・捨札・除外は右の列にあるので帯には出しません
  ゲームから除外されたカードがあると、山札・捨札の下に「除外 N」が出ます。捨札と同じく、
  乗せる（スマホはタップ）と除外されたカードが新しい順に全部大きく並び、1 枚をタップすると詳細が出ます
- デッキ構築: 全 1,832 枚の一覧からクリックで追加・右クリックで削除、保存。種類・カテゴリ・弾・コスト・BP で絞り込み、
  文字列検索（カード名・効果文・特徴・作品名・カード番号。スペース区切りで AND、ひらがな／カタカナ・全角／半角を区別しない）。
  デッキ名は上部の欄で付け替え（検索欄・デッキ名欄はホストページの `<input>` をキャンバスに重ねたもので、スマホの IME が使えます）
  始め方のメニュー（編集・空のデッキ・元にする スターター 46 種…）は 12 行ずつ表示し、下の「▲ 前へ / ▼ 次へ（N件）」のタップ、
  メニュー上の上下スワイプ、ホイールで先の行へ送れます（スマホでも 11 個目以降のスターターを選べる）。
  長いスターター名は「（type A：…」の部分を残して省略し、同じ製品のデッキ同士が見分けられるようにしています
- デッキ一覧: デッキ構築のメニュー「デッキ一覧（カード画像で見る）」で、編集中のデッキをカード画像と「×枚数」の一覧で出します（共有されたデッキを開いたときと同じ見た目）。
  ボタンは「保存して戻る / 編集を続ける / 共有する」。
- デッキの共有: デッキ構築のメニュー「共有する（URL・テキスト・QR）」で、QR コード・URL・カードリストのパネルを出します。
  - 「URLをコピー」: 短い URL `/?d=<8文字>`（`api/share.js` が Upstash Redis に期限なしで保存。同じデッキは同じ URL）。
  - 共有されたデッキの一覧: `vercel env pull .env.local` のあと `node scripts/list-shared-decks.mjs [--out shared-decks.json] [--arena ../../packages/engine/arena-decks]`（読むだけ。`--arena` で対戦台のデッキ `shared-<id>.json` にもする）。
    保存先がないときはデッキを圧縮して入れた長い URL `/#d=RD1.…`（40 枚で約 260 文字）
  - 「テキスト（カードリスト）でコピー」: `# デッキ名` / `枚数 カードID カード名` の行 / `# 計N枚`
  - 「QR画像を保存」: デッキ名・枚数・QR・URL を入れた PNG。PC はダウンロード、スマホは共有シート（写真に保存・LINE に送るなど）
  - 共有された URL を開くと、タイトルの上にカード一覧が出て「保存してデッキ構築で開く / 保存して自分のデッキで対戦 / 取り込まない」を選べます
    （同じ名前・同じ中身のデッキがすでにあれば増やさずにそれを使います）
  - デッキ構築の始め方「テキストから取り込む」: カードリストを貼り付けて新しいデッキにします。読むのはカード ID だけで、
    枚数は前（`3 RS-057`）でも後ろ（`RS-421 ×3` / `RS-421 3枚`）でもよく、読めない行は知らせて飛ばします
  - コピーと QR 画像の保存はホストページがクリックの中で直接行います（クリップボードと共有シートはクリックの中でしか使えないため。
    ゲスト側はボタンの矩形を `rs.actions` で送るだけ）
- スマホを縦に持つと、縦積みのスマホ用レイアウトに切り替わり、タップで操作します。
  幅 400 未満の狭いスマホでは、上の「共有／設定／対戦をやめる」を小さくし、ターン表示は入らなければ 14px →「自分の番」→「…」の順に縮めます。
  「ターン終了」は 1 行に入らなければ 2 行、カードの BP の札は 4 桁が入る幅（36px）を取り、タイトルの自動進行の説明は「…」で切ります
  カードのメニュー・全操作・選択ウィンドウのボタンは 1 行を指の大きさ（論理 44px、幅 390 の画面で約 40px）にして間を空け、
  下のヒントは収まる長さなら 14px（約 13px）で出します
- カードのメニューは、カード名の下に「必要パワー0 ・ BP1000 ・ S ・ WB」と効果の 1 行目を出します（詳細を開かなくても何のカードか分かるように。
  client-core の `popupCardInfo`、GuiBox の `info`）
- フェイズの表示はタブではなく段階表示です。スマホは「スタート › チャージ › …」と並べ、今のフェイズをオレンジの字と下線、
  済んだフェイズを暗い字にします。PC は右の列に番号付きで並べ、今のフェイズの左にオレンジの線を引きます（押せるボタンに見えないように）
- 全操作（すべての操作）は「すべての操作（カードごと）」として、カードごとに 1 行にまとめ、そのカードでできる操作をボタンで横に並べます。
  1 行に入らないときは共通の語尾を省きます（「パワーにチャージ」「コマンドにチャージ」→「パワー」「コマンド」）。同じカードが 2 枚あるときは
  場所（自手札1 など）をカード名の側に付けます。カードに結びつかない操作は最後に 1 行ずつ。十字キーでは今まで通り 1 操作ずつ動きます
  （client-core の `openAllList`・`groupedLayout`、GuiBox の `groups`）
- スマホの長押しは、押して少し（約 0.1 秒）たつとカードが少し浮き、周りの点の輪が時計回りに光っていきます。輪が一周すると
  カードの全体表示が開き、振動に対応した端末（Android の Chrome など）では短くブルッとします（iPhone の Safari は振動できません）
- 「ターン終了」は、まだできることがあるとき（アタック・ストライクできるユニット、未チャージ、出せるカードなど）は
  1 回目でボタンが赤い「もう一度で終了」になり、何を飛ばすかを帯で出します。もう一度押すと終了します（約 3 秒か、何か操作すると取り消し）。
  飛ばすものがなければ 1 回で終わります
- 共有: 対戦中に上の「共有」を押すと、その場面（盤面・フェイズ・選択待ち・ログ）の URL をクリップボードにコピーします。
  開いた人は同じ場面から CPU 相手に続きを遊べます（デバッグで盤面を伝える用。結果は戦績に残りません）。
  URL は短い形 `/?s=<8文字>`（盤面は `api/share.js` が Upstash Redis に 30 日保存）で、保存先がないときは
  盤面を圧縮して入れた長い形 `/#s=RS1.…`（終盤で約 2,000〜3,500 文字）になります。クリップボードに書けないブラウザでは URL を表示します
  PC では上部の通知（自動進行の終了など）は「共有」ボタンの手前で止まり、通知が出ていても「共有」を押せます
- 対戦の記録: 人と CPU の対戦が終わると、種・デッキ・指した手の全部（client-core `app/gameRecord.ts`）を `api/share.js` に送ります（画面には出しません。
  共有した盤面から続けた対戦と、CPU 同士の自動対戦は送りません）。CPU の負け方を調べるためのもので、
  `node scripts/list-game-records.mjs --env <読み取り専用の鍵のファイル> --out game-records.json` で読み出し、
  `packages/engine/scripts/replay-game-records.ts` でエンジンで再生して CPU の負けた対戦を並べます
- 対人戦（オンライン）: タイトルの「対人戦（オンライン）」で、デッキと先攻（ランダム／自分が先攻／相手が先攻）を選んで「部屋を作る」と、
  招待 URL `/?m=<8文字>` と QR が出ます。相手がそれを開いてデッキを選んで参加すると対戦が始まります（ホストの画面は 2 秒ごとに参加を確かめます）。
  判定はサーバー（`api/match.js`）がして、ブラウザには自分に見える盤面だけが届きます（相手の手札・山札の中身・シードは来ません）。
  操作は 1 手ずつ送り、答えが来るまで「送信中…」。相手の手番は 1 秒ごと、自分の手番は 3 秒ごとに問い合わせます。
  通信が切れたら同じ手を同じ番号で送り直します（サーバーは 1 回だけ適用）。上の帯に手番の人の残り時間（1 ターン 3 分、相手の手番中の選択は 30 秒）を出し、
  時間切れはサーバーが自動で進め、3 回目で負けです。投了は右上のボタンを 2 回。部屋とトークンは localStorage（`rs.online.v1`）に入れるので、
  再読み込みしても同じ対戦（または相手を待つ画面）に戻ります。盤面の共有と CPU 戦の戦績には入りません。対戦中の盤面では相手を「相手」と呼びます。
  結果画面では「お互いのデッキを公開する」（両者が押したときだけ相手のデッキを「×枚数 名前」で並べる）ができます。相手が押すとボタンの文言が変わります（2 秒ごとに確認）。
  再戦は API（下の `op:"rematch"`）と `src/postGame.ts` にありますが、初版では画面にボタンを出していません
  サイトが更新されて表示の形式が変わったときは「ページを再読み込みしてください」と出します（再読み込みで続きから）。
  決着した対戦は、CPU 戦と同じく対戦の記録として保存します（画面には出しません。下の「対人戦の部屋」）
- 相手の手の再生: 相手（CPU・対人戦の相手）の手は、盤面の上で1手ずつ見せます（`src/ReplayLayer.tsx`、手順は client-core `session/replay.ts`）。 相手の効果で動いたカードは、元の場所に「撃破」「手札へ」「ホールド」などの札を付けて、行き先の方へ消えていきます（自分のカードは赤、相手のカードは青）。場に出たユニットは光らせます。モーフは入れ替わったユニットを光らせて見せます。 追加ドローや山札からのサーチ、自分のストライクで相手の山札の上がダメージになったときは、裏向きのカードと枚数だけのお知らせを出します。
  ラッシュはカードが枠に落ちてきて光り、NC は水色の輪、アタックはカードが相手のユニットまで飛んでぶつかって戻り、ストライクはカードを持ち上げて
  その場に叩きつけ（衝撃の輪・盤面が少し揺れる・帯に「＋1 ダメージ」）、カウンター・オペレーションはカードを真ん中に大きく出し、
  ダメージで相手が裏返したパワーはそのカードが裏返ります。スマホでは画面の中ほど（自分のラッシュエリアの上。アタック・ストライクが当たるバトルエリアは隠さない）、PC では両軍の間の右寄りに、カード画像・種類・「相手の操作」・何をしたかのお知らせを出します。
  1手は約 1.6〜2 秒で自動で次へ進み、たまると早送りします。相手の手を見せている間は盤面の操作を受け付けず、選択ウィンドウもその後に開きます
  （例: 相手のストライクの後に、裏返すパワーを選ぶ窓）。自分のアタック・ストライクも同じ動きをしますが、お知らせは出ず、操作も止めません。
  自分のストライクで相手がパワーを選んでいる間は「相手が裏返すパワーを選んでいます…」と出します。CPU 戦では見せ終わるまで CPU は次の手を待ちます
- 保存（設定・自作デッキ・戦績）は localStorage（キー `rs.settings.v1` / `rs.decks.v1` / `rs.records.v1`）

## 構成

```
src/main.tsx        エントリ
src/app.tsx         画面の切り替えと入力（マウス・タッチ・キー → client-core の論理入力）
src/TitleView.tsx   タイトル（フレックスレイアウト + focusable なボタン）
src/MatchView.tsx   対戦画面（GuiView を client-core の矩形どおりに描く）
src/ReplayLayer.tsx 相手の手の再生（光る・落ちる・ぶつかる・叩きつける・大きく出す・裏返す動きとお知らせ）
src/DeckView.tsx    デッキ構築（DeckBuilderView を描く）
src/ResultView.tsx  結果画面（対人戦では投了・時間切れ・無効試合も）
src/online.ts       対人戦: /api/match の呼び出し、招待 URL（?m=）、部屋とトークンの保存、RemoteSession が使う送受信（fetchTransport）
src/lobby.ts        対人戦のロビー（部屋を作って待つ・招待から参加・再読み込みで戻る）の状態
src/OnlineView.tsx  ロビーの画面（デッキ・先攻の選択、招待 URL と QR、参加）
src/postGame.ts     対人戦の結果画面の再戦・デッキ公開（相手の希望を 2 秒ごとに確認し、再戦が決まったら新しい部屋へ）
src/cardArt.ts      カード画像テクスチャ（ホストがデコードしてアップロード）
src/engine.ts       ホストが読み込んだエンジン（globalThis.__rsEngine）を EngineApi として渡す
src/platform.ts     ブラウザ用 Platform 実装（localStorage、プライベートウィンドウではメモリ）
src/share.ts        共有 URL を作る・開く（gzip + base64url、/api/share）
src/deckShare.ts    デッキの共有 URL を作る・開く（RD1.、/api/share の deck）
src/DeckSharePanel.tsx  デッキの共有パネル・共有されたデッキの確認・テキスト取り込みの描画と当たり判定
src/qr.ts           QR コードのモジュール計算（qrcode-generator。描画はホストの globalThis.__rsQr）
api/share.js        Vercel Function: 共有された盤面とデッキを Upstash Redis に保存・取得、対戦の記録を保存（開発用サーバではメモリに保存）
api/match.js        Vercel Function: 対人戦の部屋（作る・参加・操作・投了・取り消し）。Upstash Redis に保存（開発用サーバではメモリ）
server/entry.ts     api/match.js が使うエンジン部分の入口。scripts/build-server.mjs が server/match-engine.mjs（git に入れない）に束ねる
src/ui.tsx          画面共通の描画ヘルパ
host/               ブラウザホスト（index.html, host.js）
scripts/            ビルド・開発用静的サーバ・フォント取得・pocket check
```

対戦とデッキ構築の配置は `client-core/src/view/webGui.ts`（`computeWebGuiGeometry` /
`computeWebDeckGeometry`）で、Vita 版と同じ `GuiMatch` / `DeckBuilder` にこの配置を `AppController` の `layouts` として渡しています。

ホスト（`host/host.js`）は PocketJS の WASM コアを全画面の canvas で動かします。

- 論理解像度は横長ならウィンドウに合わせて 1024×640〜1680×1050（範囲外は canvas を拡大縮小）、
  縦長（スマホ）なら幅 360〜600 でウィンドウの縦横比に合わせます（幅 360〜600 のスマホは縮小なしの等倍。幅 320 の iPhone SE 第1世代だけ 0.89 倍）。密度 2 で描画します
- マウス・ペン・タッチは PocketJS の overlay サービス経由で渡します（ボタンのホバー・クリックと、カードの当たり判定用の座標）
- キーは Vita のボタンに割り当てて渡します（下の表）
- カード画像（`apps/web/public/cards` のコピー）はブラウザでデコードしてテクスチャにします
- ルールエンジン（`dist/engine.js`）は UI と別ファイルの ESM として読み込みます
- 入力欄は文字 16px 以上、viewport は `maximum-scale=1`、ページ全体を `touch-action: manipulation` にして、iPhone で入力欄に触れたときの自動ズーム・ダブルタップズームを止めています（入力を終えたらキーボードでずれたページ位置を戻します）
- テスト用に `window.__rsApp`（`controller`・`lobby`・`postGame`・`buttons()`・`pile(player)`・`peek()`（拡大表示中のゾーン）など）を公開しています

## 操作

| 操作 | マウス | キー |
|---|---|---|
| カードの詳細 | 乗せる | ←→↑↓ |
| カードの操作・決定 | クリック | Enter / Z |
| 戻る・閉じる | 右クリック | Esc / Backspace / X |
| フェイズ終了 | 右の青いボタン | Space / E |
| すべての操作 | 右のボタン | Tab / S |
| ログ | 右のボタン | L / Q |
| デッキから 1 枚抜く（デッキ構築） | 右クリック | Delete / A |
| 検索欄へ（デッキ構築） | 検索欄をクリック | / |

ログは開いたまま遡れます。PC はログの上でホイール、スマホはログを上下にスワイプ（下へ引くと古い行）。見出しの「▲N行／▼N行」は上と下に隠れている行数です。ターンが替わるたびに「━━ ターン5：CPUのターン ━━」の行が入ります（ログは新しい 1000 行まで残します）。

スマホ（縦持ち）ではカードをタップすると詳細と操作が出ます。枠の外のタップで閉じます。ログは下の「ログ」ボタンだけで開き、盤面の空いた所をタップしても開きません（開いたログは、ログの上でもログの外でもタップで閉じます）。選択ウィンドウが出ているときは、枠の外をタップするとウィンドウをしまって盤面全体（ウィンドウの下に隠れる CPU 側も）を見られ、空いた所か「ログ」のタップで選択に戻ります（PC の L・枠の外クリックと同じ）。

## ビルドと実行

PocketJS のツールチェーンは Vita 版と共用です（`apps/vita/toolchain`、npm workspace の外）。リポジトリのルートで:

```sh
npm ci
cd apps/web-pocket
npm run setup        # apps/vita/toolchain に PocketJS を入れ、Noto Sans JP（通常・太字）を .cache/fonts に取得
npm run web:dev      # dist/ をビルドして http://127.0.0.1:8140/ で配信
```

| コマンド | 内容 |
|---|---|
| `npm run web:build` | `dist/` を作る（エンジン・UI・カード画像すべて） |
| `npm run web:build:app` | UI とホストだけ再ビルド（エンジンとカード画像は前回のもの。engine / cards を変えたら `web:build`） |
| `npm run web:serve` | `dist/` を http://127.0.0.1:8140/ で配信（`node scripts/serve.mjs --port=…` で変更可。開発用。`/api/share` と `/api/match` はメモリに保存） |
| `npm run web:exile-test` | ブラウザ（Playwright）で除外の表示を確認（PC・スマホ。除外 0 枚で何も出ない／「除外 N」行（帯には出さない）／乗せる・タップで新しい順に全部並ぶ）。先に `web:build` |
| `npm run web:online-test` | 2 つのブラウザ（PC のホスト・スマホのゲスト）で対人戦を確認（部屋を作る → 招待 URL で参加 → 両方が自分の選べる手を 60 手送る → 相手の手札が「?」で本当のカード ID が届かない → ゲストの再読み込みで同じ対戦に戻る → 投了ボタン 2 回で両方に結果 → デッキ公開の同意（片方では届かない））。`-- --shots=<dir>` で画面写真、`-- --base=https://…` で公開中のサイトに対して。先に `web:build` |

## Vercel で公開

`vercel.json` に設定があります。Next.js 版で使っていた Vercel プロジェクトをそのまま PocketJS 版に切り替えます
（Project → Settings → Build and Deployment）。

1. **Root Directory** を `apps/web` から `apps/web-pocket` に変える（「Include files outside the root directory」は有効のまま）
2. **Framework Preset** を `Other` にする。Build / Install / Output の上書きはオフ（`vercel.json` の値が使われます）
3. Node.js は 20 以上（既定の 22 で可）
4. Deployments から最新の main を **Redeploy**

ビルドはリポジトリ全体の `npm ci` → PocketJS ツールチェーンの `npm ci` → フォント取得 → `scripts/build.mjs` の順で、
`dist/` を静的サイトとして配信します。対人戦の `api/match.js` が読むエンジン（`server/match-engine.mjs`、約 9 MiB）は
installCommand の最後の `scripts/build-server.mjs` で作ります（関数の束ねより前にあるように）。

### 共有 URL の保存先（Upstash Redis）

短い共有 URL には保存先が要ります。Project → Storage から Upstash の Redis（無料プラン）を作り、このプロジェクトに Connect すると、
`KV_REST_API_URL` / `KV_REST_API_TOKEN` が環境変数に入り、`api/share.js` が使います（`UPSTASH_REDIS_REST_URL` / `_TOKEN` の名前でも可）。
環境変数を足したあとは Redeploy が要ります。

- `POST /api/share {"code": "RS1.…"}` → `{"id": "k3F9xQ2a"}`、`GET /api/share?id=…` → `{"code": …}`
- 1 件 64 KiB まで、30 日で自動削除。保存先がなければ 503 を返し、アプリは長い URL をコピーします
- デッキ: `POST /api/share {"deck": "RD1.…"}` → `{"id": …}`、`GET /api/share?d=…` → `{"deck": …}`。
  ID は中身の SHA-256 から作るので同じデッキは同じ ID（2 回目は何も増えません）。期限なし。
  2,048 文字まで、サーバで展開して `{v:1, name, cards}` のカードリストであることを確かめたものだけ保存します
- 対戦の記録: `POST /api/share {"game": "RG1.…"}` → `{"ok": true}`。キー `game:<時刻>-<8文字>` で 1 年保存し、読み出す API はありません
  （`scripts/list-game-records.mjs` が Upstash から直接読みます）。256 KiB まで、サーバで展開して `{v:1, seed, humanDeck, cpuDeck, actions}` であることを確かめます

### 対人戦の部屋（`api/match.js`）

同じ Upstash Redis を使います（保存先がなければ 503 `no_store`）。

- `POST {"op":"create","deck":…,"first":"host|guest|random"}` → `{"id","token","view"}`（ホスト = player1）、
  `POST {"op":"join","id","deck":…}` → `{"token","view"}`（ゲスト = player2。もう始まっていたら 409 `taken`）
- `GET ?id=&t=<token>[&v=<版>]` → `{"view"}`。`v` が今の版と同じなら `{"unchanged":true}`（盤面を送らない）
- `POST {"op":"act","id","t","seq","version","action"}` → `{"result","view"}`。同じ `seq` の再送は 1 回しか適用しません
- `POST {"op":"resign",…}` → `{"view"}`、`POST {"op":"cancel",…}` → `{"ok":true}`（ホストが参加前だけ）
- 終わった対戦だけ: `POST {"op":"rematch",…}`（再戦の希望。両者そろうと新しい部屋 `post.rematch.id` を、同じ席・同じデッキ・先攻を逆にして始め、
  両者とも今のトークンで入れる）、`POST {"op":"reveal",…}`（デッキ公開の同意。両者そろうと `post.reveal.deck` に相手のカード番号の並び）。
  終わった対戦の答えには `post`（`rematch: {you, them, id?}`、`reveal: {you, them, deck?}`）が付き、変わると版番号が進むので `?v=` の問い合わせでも気づけます
- 決着した対戦（勝者がいて 1 手以上）は `game:<時刻>-<8文字>` に対戦の記録を 1 回だけ保存します（1 年。CPU 戦の記録 RG1 と同じ形に
  `pvp: true`・`firstPlayer`・`reason` を足したもの、engine `matchRecord`。player1 = 部屋を作った人）。
  `scripts/list-game-records.mjs` は CPU の勝ち負けに数えず、`packages/engine/scripts/replay-game-records.ts` は再生して `--nn-out` の学習用の局面に入れます
- `deck` は `{"starter":"<id>"}` か `{"cards":["RS-001",…]}`。成功した答えにはサーバーの時刻 `now` が付きます（残り時間の表示用）
- 鍵 `match:<id>`、値は「改訂番号|JSON」（1 部屋 約 130 KiB）。最後の書き込みから 6 時間で消えます。書き込みは改訂番号を Lua で比べて
  読んだときのままなら通し、負けたら読み直して 4 回までやり直します。トークンは SHA-256 だけを保存します
- 持ち時間は誰かが読むか送るたびに確かめ、過ぎていればサーバーが自動で進めて保存します
- 表示には形式の版 `format`（engine `MATCH_VIEW_FORMAT`）が入り、画面の知らない版なら画面は再読み込みを案内します
